# 俄罗斯钓鱼4筛选推荐工具

## 启动

双击 `启动俄钓4筛选器.bat`。首次运行会创建 `.venv` 并安装依赖，随后直接使用本地缓存打开 Streamlit 页面；联网更新由页面左侧“开始刷新”在后台执行。

也可在 PowerShell 中运行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-local.txt
.\.venv\Scripts\python.exe refresh_data.py
.\.venv\Scripts\python.exe -m streamlit run app.py
```

## 当前功能

- SQLite 本地缓存。
- RF4DB 公开下载镜像天气 D0～D7 采集。
- RF4DB 个人小时收益榜采集。
- RF4DB 公开地图图鉴的18张地图底图与坐标校准独立缓存；地图显示不再依赖该地图是否进入个人收益榜。
- RF4DB 最近20页普通渔获和20页星鱼渔获采集、唯一记录去重累积。
- RF4 官方本地化站点中国区完整周榜采集，单独作为高质量记录活跃证据。
- RF4MAP 公开点位榜自动采集到末页，缓存社区坐标、鱼种、饵料、卡线与渔获数。
- RF4-STAT 按地图采集公开渔获活动表，规避单次查询100条上限并在本地去重累积；锁定天气不采集。
- 鱼种、饵料、钓组使用中文页面数据；页面不回退显示英文。
- 收益详情坐标采集，可区分点位小时收益证据与仅地图收益背景。
- 推荐详情使用地图级本地缓存展示各来源的真实坐标点位/拖钓路线，并在来源提供时标注方向、卡线和深度；只有坑位名而无坐标时不伪造标点。
- 当前小时/下一小时基础推荐。
- 搬砖按“地图+点位”推荐；挪威海暂用明确标注的工具聚类网格。
- 蹲星按“地图+鱼种”推荐。
- 等级、水域、鱼种、天气、星级、坐标筛选。
- 筛选条件批量提交，选择过程中不触发整页重新计算。
- 数据刷新在独立后台进程执行，可随时中止并保留现有缓存。
- 数据来源、刷新状态和失败缓存回退。

## 筛选与刷新

RF4-STAT公开上鱼和公开帖子随页面“开始刷新”及分级定时任务自动采集。旧的普通浏览器书签、剪贴板导入、单独帖子刷新和专用手动采集按钮已经退役；历史导入数据继续保留并参与稳定ID去重和分析。

帖子每批最多10页（最新3页＋历史最多7页），间隔至少3秒，并从本地断点逐批向首次补采锚点前90天推进。达到批次上限只代表这一批结束；历史边界未核验前不表示已完成90天。遇到403、429或安全验证时停止并保留已有缓存。坐标与多饵料在非搬砖推荐详情的“社区证据”展示；帖子不会自动给旧渔获补坐标。受限评论、原图、推算天气和来源估算收益不进入模型。

RF4-STAT 当前统一使用中文站 `https://cn.rf4-stat.com/fishing/`，包括浏览器启动页、逐地图采集及新记录详情链接；原有缓存继续保留。

所有公开来源统一通过项目专用Chrome通道访问；程序不读取日常浏览器配置，不自动点击或绕过安全验证。网站要求验证或拒绝访问时，本轮来源标记失败并继续使用最近成功缓存。

先完成左侧条件选择，再点击“应用筛选”。选择下拉项时页面不会重新计算。

“开始刷新”只在用户主动点击后运行；刷新期间仍可浏览已有缓存，必要时点击“中止刷新”。刷新完成后，再次应用筛选即可载入最新数据。

普通刷新只抓取低延迟实时窗口。需要逐批补采历史时，在项目目录运行：

```powershell
.\.venv\Scripts\python.exe backfill_history.py --batch-pages 100 --target-days 30
```

只补充可用于天气/温度习性观察的带条件流时可运行：

```powershell
.\.venv\Scripts\python.exe backfill_history.py --record-pages 0 --condition-pages 100 --target-days 30
```

任务会在 `data/history_backfill_state.json` 分别保存普通流和条件流的下一页位置，可重复执行续传；单批最多限制为 500 页，避免长时间占用页面刷新。

## 重要口径

天气预报温度和渔获即时温度不是同一个时刻的数值，必须分开保存。上星统计使用用户日暴露；鱼种习性发生变化时历史与近期禁止混合。完整规则见 `DEVELOPMENT.md`。

## 公开网页版

公开部署入口为 `streamlit_app.py`。它不会访问来源网站、启动采集器或修改发布数据；筛选偏好只在各自网页会话中生效。

本地主机刷新完成后生成脱敏公开数据：

```powershell
.\.venv\Scripts\python.exe export_public_snapshot.py
```

输出位于 `public_data/`：

- `core.sqlite3`：地图、天气、收益、刷新覆盖状态等核心数据。
- `weeks/YYYY-Www.sqlite3`：按北京时间自然周拆分的渔获、社区证据和周榜数据。
- `runtime.sqlite3.gz`：由同一份脱敏快照生成的预组装运行库，仅用于加快云端冷启动。
- `manifest.json`：所有文件的大小、SHA-256、周次和行数清单。

公开快照会删除周榜玩家名、社区原始载荷、内部错误正文和本机绝对地图路径。云端优先校验并解压预组装运行库，再检查数据库完整性和关键表行数；旧版清单仍可回退到逐周分片组装。任何文件缺失或校验失败都会拒绝加载不完整数据。

运行 `安装自动刷新任务.ps1` 后，本地主机还会每小时执行一次公开发布：先在临时目录导出并校验脱敏快照，无实质变化时跳过；有变化时只提交 `public_data/` 并推送到当前 GitHub `main` 分支，由 Streamlit Community Cloud 自动部署。工作区有未提交改动、分支或远端不匹配、校验失败时都会停止，继续保留云端上一版数据。任务使用本机 Git Credential Manager 中已有的登录凭据，不在仓库保存令牌。

可查看 `data/public_publish_state.json` 和 `data/logs/` 中的本机状态与日志；这些文件不会提交。当前 GitHub 高频快照是未接入对象存储前的过渡方案，仓库历史持续增长后应迁移到版本化对象存储。

Streamlit Community Cloud 部署参数：

```text
Repository: ghoomt03-sketch/rf4info
Branch: main
Main file path: streamlit_app.py
```

首发版本将公开分片随代码仓库部署。后续高频更新应改用对象存储，只上传发生变化的周分片并最后更新清单，避免用 Git 保存大量重复数据库历史。
